# Style Guide Output Format

## Document Analysis

- Document type
- Audience
- Channel
- Selected tone
- Applied glossary or project rules

## Findings

For each inconsistency, report:

- Category
- Observed variants and frequency when available
- Recommended standard
- Confidence
- Reason
- Whether the change is required or optional

## Consistent Version

Provide the revised text only when the user requests rewriting or when the inconsistency materially harms usability.

## Project Style Summary

End with reusable rules for:

- Tone and formality
- Preferred terminology
- Numbers, dates, and units
- List and heading format
- Quotation and emphasis
- CTA and emoji policy

## No Finding

If the document is already consistent, say so and do not manufacture changes.
